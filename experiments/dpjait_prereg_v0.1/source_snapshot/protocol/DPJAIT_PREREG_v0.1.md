# 预注册协议 v0.1：DPJAIT 第三装置上的视角—时刻分配与无参考链复现

状态：**v0.1，定稿待冻结。** 冻结后（`freeze` 写入源码与本文件哈希）任何改动都必须以新版本号另立文件，旧版本的预测照常评分并报告。

目的：把 DPJAIT 开发切片上的**回溯性**发现变成在同一装置的未见记录上的**前瞻性**检验。全部依据来自 [`reports/DPJAIT_CHAIN_DEV_2026-09-19.md`](../reports/DPJAIT_CHAIN_DEV_2026-09-19.md) 与 [`reports/DPJAIT_AUDIT_2026-09-19.md`](../reports/DPJAIT_AUDIT_2026-09-19.md)。所有路程预测在计算任何确认窗口的参考路程之前封存。

与 Lyon v0.3 的关系：Lyon 受限数据仍未到手；DPJAIT 已按 2026-09-19 的决定升为第三装置（`paper/SUBMISSION_PLAN.md` §2）。Lyon 协议不作废，数据若到手照常评分，届时作为第四装置。

## 1. 装置与被测量

- **真实**：4 台 RGB 相机（每条记录从 5 个序列号中取 4 个），1924×1082，**25 fps**，共享内参，4 项畸变；参考为 Vicon **100 Hz**、机上非对称十字 4–5 个标记。参考帧 = 4 × 视频帧。
- **仿真**：8 台相机，1920×1080，25 fps，米制、无畸变；参考为 `dronN_pos_25.csv` 的**精确位姿，25 Hz**，与视频同率。
- 标定约定（实测确定，与列名不符）：`cam_or_*` 为 Rodrigues 向量（world→cam），`cam_x/y/z` 为**平移向量 t，不是相机中心 C**。
- **被测量**：单架无人机的参考点在 4.0 s 窗（100 视频帧）内的轨迹弧长（m）。
  - 真实侧参考点 = Vicon 十字标记质心，参考值 = **100 Hz** 折线长度。
  - 仿真侧参考点 = `pos_25.csv` 的无人机原点，参考值 = **25 Hz** 折线长度。
  - **两者不是同一个量**（参考率不同），真实与仿真的数字**不得并入同一张表**，必须分列并各自标注参考率。
- 力臂：YOLO 框中心位于十字质心下方约 116 mm。路程对共同平移不变，故力臂**不作为长度的不确定度分量**；进入误差预算的是其散布（开发集 3D rms 约 30 mm）。

## 2. 二维观测：两条臂，观测同一批像素

两条臂都用**发布的 YOLOv5 框中心**（`dl_data/*.csv`），不重新检测。唯一区别是"一个框如何绑定到一架无人机"：

| 臂 | 身份来源 | 对应物 |
|---|---|---|
| `annotated`（**主臂**） | 参考位置投影后取最近框，门 **60 px** | MCalib 发布者质心缓存、`lyon_observe.py`；与前两装置同构 |
| `free`（**主臂**） | 仅多视角几何：对极门 20 px → 重投影支持 20 px → 贪心互斥分组 → 3D 最近邻连轨（速度上限 6 m/s、松弛 0.30 m） | 本项目首条无参考链 |

**两条臂都是主臂**：`annotated` 用于与 MCalib / Lyon 同链比较，`free` 用于回答"标注假设值多少"。

门限 20 px 的来源（**不调参、不需要参考轨迹**）：四条独立记录上三角化重投影残差中位 6.0–6.6 px，按 Lyon 的"3 倍装置残差"规则取 20 px。60 px 的标注门取为力臂投影（约 22 px）的约 3 倍。

`free` 臂的"轨迹 → 无人机"指派**只用于评分**（决定与哪条参考比较），不改变任何测量点；按窗内逐时刻距离中位数做一对一贪心匹配。

## 3. 窗口资格：参考无关

开发集上多数多机记录的无人机长时间静止，使被测量接近 0、比较退化。确认集**不得用参考轨迹挑窗**，因此资格由一条**参考无关**的规则决定：

- **二维运动代理** = 各相机上该窗内框中心二维折线长度的**跨相机中位数**（像素）。
- **资格阈值：代理 ≥ 75 px。** 标定自开发记录 R02/R03：代理与三维参考路程相关系数 **0.894**（n=30），比例约 **150 px/m**，故 75 px ≈ 0.5 m。
- 单机记录：代理按该记录唯一的框序列计算。
- 多机记录与仿真记录：代理按**全场景**框中心总位移的跨相机中位数计算（不需身份），窗内全部无人机一并入选。
- 资格判定在 `predict` 阶段计算并随预测封存；不合格窗不进入分母，也不进入任何统计。

## 4. 时间窗、采样网格与预算点

- 窗长 **4.0 s = 100 视频帧**，从第 0 帧起不重叠切分，尾段丢弃；窗跨 [f₀, f₀+100] 闭区间。
- **m 网格**：{4, 6, 8, 10, 13, 17, 20, 25, 34, 50, 100}，均匀 `f₀ + round(linspace(0, 100, m))`，重复索引合并并记录实际时刻数。
- **预算点** B = k·m：真实侧 {40, 52, 68, 80, 100, 136, 200}；仿真侧另加 272。每个 k 取 |k·m − B| ≤ 0.12·B 中 MAE 最小的 m。
- **主估计器 `polygon`**（选定依据：开发集上 `limited_arc` 只在 m ≤ 6 更优，m ≥ 8 一致更差）；`limited_arc` 全程并报。

## 5. 测量链

成本模型：一个相机帧在一个时刻被读取记 1 单位，B = k·m；观测缺失照常计费。

1. 观测：§2 的两条臂。
2. **三角化：两条臂都用线性 DLT，取该臂在该时刻绑定到的全部视角。** 本协议**不使用** MCalib 冻结的 4 px / 20 mm 空间门控——开发集已证该阈值对本装置过紧（残差 6 px 量级），且本轮要隔离的是身份，不是门控。门控作为次要臂留待后续版本。
3. 估计器：`polygon`（主）、`limited_arc`（并报）。
4. 失败策略：某时刻可见视角 < 2 则该时刻删除；**任一端点缺失则窗失败**；`free` 臂另加"轨迹未覆盖两端点"即失败。失败入分母；配对比较只用共同完成窗。

## 6. 视角子集

- 真实侧 k ∈ {2, 3, 4}：**全部子集**（6 对 / 4 三元组 / 1 全集）。
- 仿真侧 k ∈ {2, 3, 4, 5, 6, 7, 8}：k ≤ 3 与 k = 8 取全部；k ∈ {4, 5, 6, 7} 取**固定种子随机 10 个子集**（`numpy.default_rng(20401 + k)`，见 `dpjait_chain_compare.subsets`）。
- 三视角的主统计量是全部三元组的**中位数**。

## 8. 预注册假设

MAE 单位 mm。开发集数值列于括号内**仅作对照，不是门槛**。全部按主臂 `annotated` + 主估计器 `polygon` 评估，除 H3 另有规定。

**H1 Goldilocks 点很低。** 真实装置在 k=4 下的 m\* ∈ **[6, 13]**；仿真装置在 k=8 下的 m\* ∈ **[20, 50]**。（开发：真实 8–10，三记录一致；仿真 25–34。）判定按各记录 m\* 的中位数。

**H2 等预算下买视角。**
- (a) 真实侧：k=4 在 **≥ 6 / 7** 个预算格获胜。（开发：21/21，三记录各 7/7。）
- (b) 仿真侧：获胜的 k 随 B **单调不降**，且获胜的 m **全程落在 [17, 50]**。（开发：k 走 2→3→3→3→4→6→8→8，m 走 20→17→25→25→25→25→25→34。）

**H3 无参考链的代价随视角数崩塌。** 在真实多机组（R14_D3、R15_D3）上，`free`/`annotated` 的 MAE 比值（各取该 k 下 `annotated` 的最优 m）：
- (a) k=2：比值 **> 3**，且 `free` 失败率 **> 0.2**；
- (b) k=3 与 k=4：比值 **< 2.5**，且 `free` 失败率 **< 0.15**。
（开发 R12_D4：7.23 / 0.33 对 1.43 / 0.06 与 0.96 / 0.06。）真实单机组上另报同一比值，预期 k≥3 时 < 2.5（开发 1.39–1.81）。

**H4 误差不是共模。** 真实单机组在各自 m\* 处，"独立传播预测 / 实测路程误差"的比值 ∈ **[0.8, 1.5]**，且显著低于 MCalib 的 6.3。（开发 1.03。）独立传播预测 = √(2·段数) × 去掉力臂后的 3D rms 散布。

**H5 视角到 k=8 不饱和。** 仿真组在 m ≥ 25 时，k=8 的 MAE 至少比 k=3 低 **1.5 倍**。（开发 S07_D8：m=34 时 237/62 = 3.8。）另报 k=2…8 的完整曲线与失败率。

**投稿判定**：
- H1 与 H2 通过 → DPJAIT 作为第三装置进入 IEEE TIM 稿件，主张"先把 m 投到该被测量的 Goldilocks 密度，余下预算买视角；DPJAIT 是该规则的第三种结局"。
- H2 通过、H1 不通过 → 结论限定为"本装置 m\* 低"，m\* 的具体区间按确认值重写。
- H2 不通过 → 稿件改写为三装置异质性，DPJAIT 降为机制章节的证据。
- H3 通过 → 稿件可声明"标注观测链的条件在 k≥3 时无害"，这是对现有最大软肋的正面补强；H3 不通过 → 保留该条件声明。
- H4、H5 只影响机制章节，不影响投稿判定。

## 9. 执行顺序与封存

1. `freeze`：本文件与 `src/dpjait_record.py`、`dpjait_sim_record.py`、`dpjait_identity.py`、`dpjait_chain_compare.py`、`mcalib_cache_observer.py`、`limited_arc_cpu.py` 的 SHA-256 写入 `freeze.json`，源码快照存档。**在跑任何确认记录之前完成。**
2. `predict`：对确认记录计算窗口资格（§3）、两条臂、全部 (k, m, 子集) 的**路程估计值**，写入 `predictions/`；**此步不读取任何参考路程**。SHA-256 与 UTC 写入 `seal.json`。
3. `score`：此时才计算参考路程并附误差。
4. `decide`：评估 H1–H5，写 `decision.json`。评分与判定**不得改动预测文件**。
5. 报告：`reports/DPJAIT_PREREG_RESULT_<date>.md`，含全部失败、两条臂、全部 m 与 k，与 MCalib / Lyon 分表并列（参考率不同，见 §1）。

注：`annotated` 臂的身份绑定需要读取参考位置以投影取框。这在 `predict` 阶段发生，但**只用于身份绑定，不计算任何路程参考值**；参考路程只在 `score` 阶段计算。该边界由代码分步强制。

## 10. 明确不做的事

- 不在确认数据上调门限（20 px / 60 px / 75 px）、窗长、m 网格、子集规则、估计器、预算点或假设方向。
- 不用参考轨迹选窗（§3 的资格规则是参考无关的）、选帧、选视角或估计。
- 不把失败窗或不合格窗从各自分母中去掉。
- 不把真实侧与仿真侧的数字并入同一张表（参考率不同）。
- 不声称"通用最优视角数"或"通用 m\*"；结论限定为该观测链在该装置上的分配面。
- 不改进 `free` 臂的关联算法（当前为单时刻几何 + 最近邻连轨的下界实现）；k=2 的结论只对这一类方法成立，不是"两视角原理上不可能"的证明。
