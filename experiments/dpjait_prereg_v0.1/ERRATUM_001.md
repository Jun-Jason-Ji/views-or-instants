# 勘误 001：R18_D1_A 只有 3 路视频

发现时间：2026-09-20，`predict` 阶段（冻结之后、`score` 之前）。
影响文件：`protocol/DPJAIT_PREREG_v0.1.md` §7 的确认集表。**冻结文件不作修改**，本勘误随运行目录一并发布。

## 事实

`protocol/DPJAIT_PREREG_v0.1.md` §7 把 **R18_D1_A 列入"真实单机"确认组**，并在同一行以"仅 3 路视频"为由排除 R17_D1_A。实际上 **R18_D1_A 同样只有 3 路视频**：

```
Real_Data/R17_D1_A/  55260362.avi  60881257.avi  61016180.avi
Real_Data/R18_D1_A/  55260362.avi  60881257.avi  61016180.avi
```

成因：落地审计阶段核对相机数时读取的归档清单在 R17_D1_A 之后被截断，R18_D1_A 的文件列表未逐条核对，写协议时按"其余真实记录均为 4 路"推断，未复核。

## 影响

这不构成协议违反——§6 规定真实侧 k ∈ {2, 3, 4} 取**全部子集**，3 路相机下 k=4 的子集集合为空，该记录自然只产出 k ∈ {2, 3}。已封存的 R18_D1_A 预测（11/11 窗合格、968 条）**全部有效**，只是不含 k=4。

逐条假设的影响：

| 假设 | 定义在 | R18_D1_A 的影响 |
|---|---|---|
| H1（m\*，真实侧 k=4） | k=4 | **不参与**。`_best_m(rows, "annotated", 4, grid)` 返回 None，`step_decide` 已按构造过滤。 |
| H2a（k=4 赢预算格） | k=2,3,4 | **不参与**。每格要求至少两个 k 有值，R18 缺 k=4，其格仍会计入 k=2/k=3 的比较——见下方"需注意"。 |
| H2b（仿真） | 仿真组 | 无关。 |
| H3（身份代价） | 真实多机组 | 无关（R18 属单机组，只作附报）。 |
| H4（误差相关结构） | 真实单机组 | **需注意**：`_error_structure` 取 `k = max(r["k"])`，对 R18 即 k=3，而其余记录为 k=4。H4 的区间 [0.8, 1.5] 是在开发集 k=4 上导出的。 |
| H5（仿真视角） | 仿真组 | 无关。 |

## 处理

1. **H1、H2a**：代码已自动排除 R18_D1_A 的 k=4 项，无需干预。H2a 的预算格若只剩 k=2 与 k=3 可比，仍会计入"k=4 是否获胜"的分母而 k=4 不可能获胜，会**低估** H2a 的通过率——这是保守方向，不予修正，但判定时必须分报"含 R18"与"不含 R18"两个比例。
2. **H4**：报告 R18_D1_A 的比值时必须标注其 k=3，不与 k=4 的记录合并取中位数；主判定使用 8 个 4 路记录。
3. 最终报告 `reports/DPJAIT_PREREG_RESULT_<date>.md` 必须复述本勘误。
4. 不新增替代记录来"补上"R18 的位置——那等于在看过部分结果后调整确认集。确认集就此为 **8 个 4 路单机记录 + R18_D1_A（3 路，k≤3）**。

## 未受影响

窗口资格规则、门限、m 网格、子集规则、估计器、预算点、假设方向与区间均未改动。冻结哈希（2026-09-20T11:15:23Z）保持有效。
