# 观察 002：多目标记录的资格代理被静止目标稀释，R15_D3 因此零窗合格

发现时间：2026-09-20，`predict` 阶段（冻结之后、`score` 之前）。
**不修改冻结文件，不调整阈值。** 本文只记录机制、量化后果并指定报告义务。

## 事实

`protocol/DPJAIT_PREREG_v0.1.md` §3 规定：多机与仿真记录的资格代理按**全场景框中心**（同一相机内全部框的质心）的二维总位移计算，跨相机取中位数，阈值 75 px。

**R15_D3 的 4 个窗全部不合格**（代理 10.7 / 21.4 / 27.3 / 19.7 px），因此该记录封存 0 条预测。

## 机制：稀释，不是抵消

在**开发**记录上核对（R13_D3、R12_D4，均已暴露，核对不消耗确认数据）：

| 记录 / 窗 | 代理 px | 合格 | 逐架参考路程 m |
|---|---:|---|---|
| R13_D3 w10 | 1448.3 | 是 | 2.15 / 1.33 / 1.81 |
| R13_D3 w9 | 106.1 | 是 | 1.35 / 0.75 / 0.74 |
| R12_D4 w11 | 548.6 | 是 | 2.41 / 3.44 / 0.95 / 0.04 |
| **R12_D4 w8** | **31.6** | **否** | 0.0 / 0.0 / **0.56** / 0.03 |
| **R12_D4 w9** | **42.1** | **否** | 0.0 / 0.0 / **0.66** / 0.04 |

R13_D3 各架运动方向不同却给出很大的代理值，说明**不存在方向抵消**。真正的效应是**稀释**：n 个目标的质心把单架的位移压低约 n 倍，所以"只有一架在动、其余静止"的窗会被判不合格（R12_D4 w8/w9：单架 0.56–0.66 m 却只读到 32–42 px）。

按此推算，R15_D3 的 10–27 px 对应单架约 0.1–0.55 m，确实处在"几乎不动到轻微移动"区间，**排除方向正确**，只是阈值对多机记录实际上更严。

## 后果

1. **H3（身份代价）的确认证据只剩 R14_D3 一条记录。** 协议 §7 原计划用 R14_D3 + R15_D3 两条。这是证据强度的实质下降，必须在结果报告中明说，不得以"两条多机记录"表述。
2. 仿真组（6–8 架）受同样的稀释影响更重，合格窗数可能显著低于 29–30。若因此导致 H2b / H5 样本不足，**按不足报告，不调阈值**。

## 不做的事

- 不降低 75 px 阈值，不改为逐架代理，不为 R15_D3 单独开特例——这些都等于在看过合格结果后调整确认集。
- 不增补记录替代 R15_D3。
- 阈值、窗长、m 网格、子集规则、估计器、假设区间一概不动；冻结哈希（2026-09-20T11:15:23Z）保持有效。

## 供下一版协议参考（不影响本次）

若有 v0.2，多目标资格应改为**逐目标代理**：先用 `free` 臂自身的轨迹（仍然参考无关）取每条轨迹的二维位移，再按目标逐一判定资格，而不是全场景质心。本次不采用，因为它会改变已封存运行的资格集合。
